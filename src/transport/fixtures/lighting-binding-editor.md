# Редактор локальных подключений

Нативная страница «Подключения» отделяет логический профиль от физических адресов. Она читает и сохраняет `lighting-local.json` в выбранном каталоге состояния либо файл, переданный `--native-lighting`. Сохранение не открывает выходы и не переключает Runtime. Источники: `src/app/lighting_bindings.rs`, `src/ui/windows/connections.rs`.

## Подключение и замена

1. Создать логическое устройство в «Устройствах» либо источник экранной подсветки.
2. В «Подключениях» выбрать этот источник. Для поддерживаемого поиска нажать «Найти устройства», явно выбрать результат. Поиск не выбирает первое устройство автоматически.
3. Проверить поля и сохранить. Незавершённые и прежние привязки можно открыть для исправления; аппаратный запуск требует отдельной полной проверки.
4. При замене сохранить новый физический адрес для прежнего логического ID. Для удалённых источников предусмотрено отдельное явное удаление оставшихся привязок.
5. В обычном интерактивном режиме нажать «Применить»: читается сохранённый файл и строится полный план отложенных фабрик. Неполные и неверные связи отклоняются до остановки прежних потоков. Применение использует общий configuration drain/persistence barrier Runtime; охлаждение не останавливается. Источники: `Local::prepare`, `Runtime::request_outputs`, `configuration_tick`.
6. При ошибке открытия можно исправить файл и применить его снова либо нажать «Вернуть». Возврат явно запускает предыдущий набор фабрик после завершения текущих потоков; сохранённый файл не переписывается. При ошибке сохранения журнала доступны «Повторить» и «Отменить»; отмена сохраняет прежний набор. Автоматического скрытого возврата нет. Источники: `runtime/outputs.rs`, `windows/connections.rs::apply_connections/poll_connection_switch`.

Верхняя строка страницы отделяет текущий режим и применённую привязку от сохранённой. Открытие потока не доказывает физическую передачу/качество: состояния передачи проверяются отдельно. Источник: `refresh_connections`, `outputs_ready`.


Неподтверждённая текущая правка блокирует уход со страницы и закрытие. Изменившийся с момента чтения файл не перезаписывается: форма сохраняет правки, предлагает перечитать файл. Это обнаружение обычного внешнего изменения перед записью, не межпроцессная транзакция против враждебного писателя. Частичные черновики не проходят полный `Local::read` для аппаратного запуска. Источники: `Workspace::assign/save`, `Local::validate_draft/validate`.

## Доказанные границы поиска

- Fusion2 и поддерживаемые Valkyrie: Windows HID metadata и проверка дескриптора без feature reports. SetupDi-список ограничен; проверяются VID/PID, family path и необходимые capabilities.
- TT LCD: существующий metadata backend и проверка display interface, без открытия потока отправки кадров.
- Монитор: Windows display descriptors. Захват рабочего стола при поиске не запускается.
- Skydimo: только CH340/COM metadata. CH340 не доказывает Skydimo, порт не открывается, запрос HEX ID не выполняется. ID нужно указать отдельно.
- Дверная BLE-лента: ручной известный MAC, автоматического поиска нет.
- ENE RAM: ручной проверенный модуль и адрес, SMBus не сканируется.
- Неизвестный протокол не становится поддерживаемым от наличия адреса.

Источники: `src/app/lighting_bindings/discovery.rs`, `src/lcd/hid_windows.rs::metadata_paths`. Сам native metadata backend на рабочем ПК в этой приёмке не запускался; стенд использует явно помеченные программные примеры.

## Остаётся

Native режим выбирается явным «Применить» в обычном окне либо `--native-lighting`; положительный native запуск на рабочем ПК не выполнялся. Snapshot не получает native activation capability, selftest использует исключительно внедрённые программные фабрики. Возврат одноразовый: он не превращает отказавший набор в новый вариант для повторного «Вернуть». Предыдущий набор хранится только в текущем процессе, режим не запоминается для автоматического аппаратного старта после перезапуска. При несовместимом изменении логической топологии старый набор отклоняется до переключения. Нет доказанной универсальной межпроцессной эксклюзивности, физической приёмки устройств или совместимости с произвольным оборудованием. Полный продукт и перенос охлаждения остаются незавершёнными.

# PawnIO wire and pinned PIIX4 image

The Rust module `src/transport/pawnio.rs` contains file verification and pure wire helpers, not a kernel transport. No DLL is loaded, no kernel device is opened, no module or driver is installed or started, and no hardware call is made by the stand commands.

The local source ABI is `../rgb-openrgb-2026-11-05/core-source-1.1/dependencies/PawnIO/PawnIOLib.h:27–73` and `i2c_smbus/Windows/i2c_smbus_pawnio.cpp:40–133,196–256,311–360,404–418`. Source passes9u64 input/5u64 output for SMBus transfers and copies the native union at input word4. The Rust packet explicitly zeroes the entire unused area; reads validate returned byte counts before parsing. The shared mutex name is taken from `i2c_smbus/Windows/i2c_smbus_pawnio.h:22`. Source selects port0, identity uses one zero input word, and sleep mode2 is the source default. These encoders are not sufficient to authorize execution.

The shipped local PawnIOLib.dll4096B has SHA-256 `c6e7c2f54643ef9cb51b9a3ec7b0efc9e204803c206f33014e39f281546ea9b4`. Craft Anything static exports evidence `ev_a217991b3606558c262d21b3840a847072c82c7fb6c28ea6cd05bdc7b85babc8` and approximate static decompile `ev_d7adf41f5d1b46010e0253083aca787a5f8a81ef29d1af123b0bd7d950d31273` support the32-byte NUL function prefix and u64 arguments, LOAD0xA1B22084 and EXECUTE0xA1B22104. The approximate lifter is not a runtime proof.

Primary source cross-check, read2026-11-06: [PawnIOLib.cpp](https://github.com/namazso/PawnIO/blob/master/PawnIOLib/PawnIOLib.cpp), [pawnio_um.h](https://github.com/namazso/PawnIO/blob/master/PawnIO/include/pawnio_um.h), [SmbusPIIX4.p](https://github.com/namazso/PawnIO.Modules/blob/main/SmbusPIIX4.p). Current upstream source may differ from the local signed module and alone does not prove its capabilities. Subsequent exact-pin AMX static decoding confirms query−1 and three-byte block support; see adjacent `pawnio-native-provenance.md` and reproducible `pawnio-amx-proof.py`. A generic block error still never proves no progress or permits fallback.

The image gate pins only this existing local file: `../rgb-openrgb-2026-11-05/core-source-1.1/dependencies/PawnIO/modules/SmbusPIIX4.bin`,42404B, SHA-256 `91f9b4b1c39e3d399ce48477a89d8f6bd3e58a2241064a4daec3a1513dff56e5`. The binary is not included in the public fixture or repository. `cargo run --locked --example pawnio_module_stand -- <local-file>` validates bytes without loading them. It succeeded for this file (`work/rgb-protocol-stand/module-image.txt`). Hash pinning confirms exact bytes, not their safety or compatibility with a particular motherboard or installed driver. Updating the pin requires a fresh review.

The native boundary now exists separately in `pawnio_adapter`, `pawnio_windows` and `ene_bus`: whole-transaction shared guard, provider/port/bound-address checks, pointer/value gates, rejection of persistent apply0xAA/SPD/remapping and terminal ambiguous errors. `Transfer::write_selected_byte` itself remains an encoder which cannot establish the destination. It is not exposed as an unrestricted native hardware API. Wire tests cover layout, address/register bounds, short/unaligned results and invalid images; native/fake stand scope and remaining physical limits are documented in `pawnio-native-provenance.md`.
